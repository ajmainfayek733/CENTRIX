## Alert Rule Engine

This component evaluates incoming events.
Instead of: `if(idle > threshold)`

create reusable rules.

```
public interface IAlertRule
{
    bool ShouldEvaluate(TelemetryEvent e);

    Task<AlertEvaluationResult> EvaluateAsync(
        TelemetryEvent e,
        PolicyDocument policy,
        CancellationToken cancellationToken);
}
```

Each rule becomes independent.
Example

```
IdleAlertRule

BlacklistedSiteRule

USBViolationRule

OutsideWorkHoursRule

ApplicationViolationRule

ScreenshotFailureRule
```

Adding a new alert should never require modifying AlertEngine.

## Recommended Design Pattern

Rather than embedding alert logic directly inside AlertEngine, use a Rules Engine + Strategy pattern:

- `AlertEngine` orchestrates evaluation and persistence.
- Each alert type (`IdleAlertRule`, `BlacklistedSiteRule`, `UsbViolationRule`, etc.) implements a common `IAlertRule` interface.
- An `AlertRepository` persists alerts and maintains lifecycle state.
- A `NotificationManager` is solely responsible for user-facing notifications (Windows Toast, tray icon, sounds).
- An `AlertStateManager` handles deduplication, escalation, acknowledgement, and resolution.
- A `PolicyManager` provides dynamically loaded policy settings without restarting the service.
