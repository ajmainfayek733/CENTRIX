## Enterprise recommendations

An enterprise-grade attendance engine should:

- Treat attendance as an event-driven state machine rather than relying on accumulated counters.
- Use UTC timestamps exclusively and convert to local time only for display.
- Validate every event sequence (login/logout, lock/unlock, idle start/end, sleep/wake) and automatically repair incomplete sessions after crashes, forced shutdowns, or unexpected restarts.
- Merge overlapping non-working intervals (idle, lock, sleep, hibernate) before subtraction to avoid double counting.
- Split sessions that span midnight into separate daily summaries.
- Support multiple concurrent Windows sessions (console, Remote Desktop, Fast User Switching) by tracking each session independently.
- Make idle thresholds, attendance rules, and recovery policies configurable instead of hard-coded.
- Ensure calculations are deterministic and idempotent so the same input events always produce the same attendance summary.
- Persist immutable raw events and derive attendance summaries from them, enabling recalculation when business rules change.
- Include comprehensive validation, diagnostics, and audit information to identify missing, duplicate, out-of-order, or corrupted events.
