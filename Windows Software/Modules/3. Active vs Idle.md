## Edge Cases

1. User jiggles mouse every 4m 59s. Should remain: `Active`
2. Mouse moves automatically. Detect Large identical movements, perfect intervals, no keyboard, no foreground changes. Mark: `Suspicious Activity`
3. Keyboard macro. Repeated intervals, repeated keys, no mouse. Flag: `Possible Automation`
4. Video conference. Watching Teams(zoom, google meet, slack, etc), no input, 40m - 1h depending on policy. Admin can add policy via Admin dashboard. Possible States: `idel` or `Meeting`.
5. Presentation mode. Powerpoint Slideshow (MS powerpoint, google slides, wps office, etc), no input,Should optionaly remain: `Presentation`
6. Long Compilation. Visual studio, video rendering, image export, video export, Blender, cad, no keyboard, CPU 80%-100%. Remain: `Active`
7. Large download, no input, CPU 0%, Remain: `Idle`.
8. Locked PC. Never: `Idle`, Always: `Locked`
9. Sleep. Never count: `Idle`
10. Hibernate. Pause all timers
11. Fast User Switching. Track: `Console Session`, `User SID`, `Session ID`
12. RDP Session. Differentiate: `Console`, `Remote Desktop`
13. VM. Detect: `Hyper-V`, `VMware`, `VirtualBox`. Useful for analytics
14. Time Change. Never rely on `DateTime.Now`. Use `GetTickCount64()` + `UTC timestamps` to avoid issues from daylight saving changes, manual clock adjustments, or NTP synchronization.
15. Agent restart. On startup `Read Last State -> Read LastInputInfo() -> Resume Session`. No duplicate sessions.
16. Explorer crash. No impact. Uses windows session APIs.
17. Multiple Monitors. Monitor `Display Count`, `Resolution Changes` should not affect activity state.
18. Tuchscreen. Treat `Pen`, `Touch`, `Stylus` as valid user input.
19. Accessibility Devices. Support `On-screen keybord`, `Accessibility keyboard`, `Eye tracking`, Switch devices` through Windows input APIs.

## Enterprise Recommendation

For a production employee tracking solution, implement an Activity Detection Engine with four cooperating components:

- **Input Monitor** using GetLastInputInfo() as the authoritative idle source, supplemented by optional low-level input hooks for richer analytics.
- **Windows State Monitor** subscribing to session, power, and workstation events (WTSRegisterSessionNotification, WM_POWERBROADCAST, lock/unlock notifications) to distinguish Active, Idle, Locked, Sleeping, and Offline states accurately.
- **Decision Engine** that evaluates multiple signals (user input, session state, power state, foreground application, optional CPU/GPU utilization) and transitions a finite state machine instead of maintaining a simple idle counter.
- **Persistent Session Manager** that records only state transitions with UTC timestamps and monotonic tick counts, enabling accurate duration calculations, crash recovery, offline operation, and synchronization with a central server.
